# blog-posts

HYGGEブログの記事データ。1記事1ファイル（JSON）。

- `build-blog.js` がここと GAS（スプレッドシート）の両方を読み、`blog/` に静的HTMLを生成する
- スラッグが重なった場合はこのフォルダ側が優先される
- `_plan.json` は次に書く記事のネタ帳（`_` 始まりのファイルは記事として読まれない）

## 記事ファイルの形

```json
{
  "date": "2026/09/10",
  "title": "記事タイトル",
  "excerpt": "一覧と検索結果に出る2行程度の説明",
  "image": "/shop-01.webp",
  "lead": "記事の頭に出す2〜3文（任意）",
  "body": "本文。段落は空行で区切る。",
  "faq": [{"q": "質問", "a": "答え"}],
  "related": ["monstera-care-kumamoto"],
  "updated": "2026/10/01",
  "slug": "kumamoto-kanyoshokubutsu-shop"
}
```

`lead` / `faq` / `related` / `updated` は任意。faq があると「よくある質問」欄と FAQPage の構造化データが付く。
記事の最後には店の案内（住所・営業時間）と「あわせて読みたい」が自動で付く（`"shopBox": false` で店の案内を外せる）。

### 本文の書式

| 書き方 | 表示 |
|---|---|
| `## 見出し` | 見出し（3つ以上で目次が自動で付く） |
| `### 小見出し` | 小見出し |
| `- 項目`（行ごと） | 箇条書き |
| `1. 手順`（行ごと） | 番号付き |
| `> 一文` | 囲みのポイント |
| `![説明](/prod-x.webp)` | 本文中の写真（説明が下に出る） |
| `**太字**` / `[文字](/blog/x.html)` | 太字・リンク（段落の中で使える） |

どれも1ブロック（空行で区切ったまとまり）単位。書式のない古い記事はこれまでどおり段落で表示される。

`image` はサイト内の相対パス。生成時に本番URLが自動で補われる。

## 更新の流れ（自動）

毎週火曜の巡回（`cockpit-pc-requests`）が `_plan.json` の先頭を1本、本格記事として書く（調べる→構成→執筆→Codexチェック）→
`node build-blog.js` → commit & push → Vercelが公開 → GBPにも記事リンク付きで投稿。
